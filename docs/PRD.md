# Web3 Farm · 多集合绑定产分平台 PRD

> 版本：v0.1 · 第一期 MVP  
> 首个集合：Nobody NFT（Ethereum）  
> 后期激励链：BSC（代币 / 空投 / 游戏）

---

## 1. 产品定位

**Web3 Farm** 是一个支持 **多个 NFT 集合** 的绑定产分平台：

- 用户在网页连接钱包，**签名证明身份**（0 gas）
- 将持有的 NFT **绑定到农场槽位**，按稀有度档位 **每日产出积分**
- 积分用于 **解锁更多槽位**；后期在 **BSC** 兑换代币、参与游戏或空投
- **Nobody** 是第一个接入集合；后续新集合通过 **配置 + 稀有度策略** 接入，无需重写主流程

## 3. 链与账户模型

```
┌─────────────────────────────────────────────────────────────┐
│ Ethereum（及未来其他 L1）                                     │
│   · 读取 NFT 持有与 metadata                                  │
│   · 第一期：Nobody ERC-721                                    │
├─────────────────────────────────────────────────────────────┤
│ 链下积分账本（PostgreSQL）                                    │
│   · 绑定关系、档位、领取记录、槽位                            │
├─────────────────────────────────────────────────────────────┤
│ BSC（第二期及以后）                                           │
│   · 平台代币 / 游戏币                                         │
│   · 快照 → Merkle Claim 或 claim 合约                         │
└─────────────────────────────────────────────────────────────┘
```

**钱包建议：** 同一 `0x` 地址用于 ETH 验 NFT 与 BSC 领奖（降低空投对照复杂度）。  
后期可选：ETH 绑资产 + 单独绑定 BSC 领奖地址（一对一）。

## 4. 档位体系（已定比例）

档位从高到低及 **倍率比例**：

| 档位 | 代码 | 倍率 | Nobody 判定规则（v1） |
|------|------|------|------------------------|
| Special | `SPECIAL` | **50** | 存在有效 `special` trait |
| Top | `TOP` | **20** | 无 special；常规属性 ≥8；平均 trait 占比 ≤ 5% |
| Full | `FULL` | **10** | 无 special；常规属性 = 8 |
| Rich | `RICH` | **2** | 无 special；常规属性 = 7 |
| Basic | `BASIC` | **1.5** | 无 special；常规属性 = 6 |
| Minimum | `MINIMUM` | **1** | 其他情况（如 <6 属性） |

**比例关系：** `50 : 20 : 10 : 2 : 1.5 : 1`

**合成规则：**

1. 命中 `SPECIAL` 时 **仅使用 50×**，不再叠加属性个数或 trait 占比
2. 无 special 时，按 **属性个数** 与 **TOP 条件** 取最高匹配档
3. `token_overrides` 人工覆盖 **优先级最高**

**日产积分公式：**

```
daily_points = base_points_per_day × tier_multiplier
```

- `base_points_per_day`：**待定（TBD）**，由运营配置，不写死在代码
- 当前代码默认值 `10` 仅供开发试算，上线前需重新评估通胀

## 5. Nobody 集合规则（策略 `nobody_v1`）

### 5.1 常规属性（8 项）

`background`, `body`, `earrings`, `face`, `glasses`, `handheld`, `head`, `skin`

### 5.2 顶档属性

`special` — 存在即为 `SPECIAL` 档

### 5.3 Trait 稀缺度

- 链上 metadata **不含** 百分比
- 平台维护 `trait_rarity_stats` 表（离线扫描全系列生成）
- 运行时查表计算 **平均占比** `avgPercent`，用于 `TOP` 判定

### 5.4 合约信息

| 项 | 值 |
|----|-----|
| 链 | Ethereum Mainnet（chainId 1） |
| 标准 | ERC-721 |
| 合约 | `0xa28d6a8eb65a41f3958f1de62cbfca20b817e66a` |
| Supply | 10,000 |

## 6. 多集合扩展模型

每个集合在 **Collection Registry** 登记：

| 字段 | 说明 |
|------|------|
| `slug` | 唯一标识，如 `nobody` |
| `chain_id` | 读 NFT 的链 |
| `contract_address` | 合约地址 |
| `standard` | `erc721` / `erc1155` |
| `rarity_strategy` | 策略 id，如 `nobody_v1` |
| `enabled` | 是否开放绑定 |
| `max_bindings_per_wallet` | 该集合单钱包最多绑几个 |
| `trait_rarity_table_id` | 稀缺度统计表版本 |

**新集合接入 SOP：**

1. 登记合约与链  
2. 采样 metadata，确认 trait 结构  
3. 选择或新增 `rarity_strategy`  
4. 跑脚本生成 `trait_rarity_stats`  
5. 配置倍率（可沿用平台默认 50:20:10:2:1.5:1 或单独 override）  
6. 内测 → 开放

## 8. 槽位机制（成本 TBD）

**建议默认值（可整表替换）：**

| 槽位 | 累计解锁积分 |
|------|--------------|
| 1 | 0 |
| 2 | 300 |
| 3 | 900 |
| 4 | 2,400 |
| 5 | 6,000 |

- **作用域：** 建议第一期 `global`（全站共享槽位）；后期可改 `per_collection`
- 一个 NFT 全局只能绑定在一个钱包；解绑后 **24h** 冷却再绑到其他地址
